## Hook System Overview

Claude Code hooks allow programmatic enforcement of rules via `settings.json`. Key concepts:

**Hook Events (most common):**
- `PreToolUse` — fires BEFORE a tool runs. Use matchers to target specific tools (e.g., `Bash`, `Edit`, `Write`, `WebFetch`). Best for preventing unwanted actions.
- `PostToolUse` — fires AFTER a tool runs. Use matchers to target specific tools. Best for validation after changes.
- `Stop` — fires when Claude is about to finish its response. Best for final checks and reminders.

**Handler Types:**
- `command` — runs a shell command. Exit code 0 = pass, non-zero = block. Stdout is fed back to Claude as context. Use `$TOOL_INPUT` for the tool's input JSON.
- `prompt` — sends a prompt to Claude for self-review. The prompt text is shown to Claude, who decides whether to proceed.

**Matcher Syntax:**
- Exact tool name: `"Bash"`, `"Edit"`, `"Write"`, `"WebFetch"`
- Regex pattern for matching tool input: use command handlers with grep/jq on `$TOOL_INPUT`

**Config Location:**
- Project-specific: `.claude/settings.json` in the project root
- User-wide: `~/.claude/settings.json` for all projects

## Examples

Example 1 — Preventing direct pushes (PreToolUse + command):
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"$TOOL_INPUT\" | jq -r '.command' | grep -qvE '\\bgit\\s+push\\b' || (echo 'Direct git push is not allowed. Create a PR instead.' && exit 1)"
          }
        ]
      }
    ]
  }
}
```

Example 2 — Requiring tests before completion (Stop + prompt):
```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Before finishing, verify: Have all new functions been covered by tests? If not, add the missing tests before completing."
          }
        ]
      }
    ]
  }
}
```

Example 3 — Lint check after file edits (PostToolUse + command):
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npm run lint --silent 2>&1 || echo 'Lint errors found. Please fix before continuing.'"
          }
        ]
      }
    ]
  }
}
```

## Instructions

Generate a hook configuration for the enforcement statement above. Return ONLY a JSON object with these three fields:

```json
{
  "hookConfig": { ... },
  "explanation": "...",
  "applyInstructions": "..."
}
```

- **hookConfig** — The exact JSON object to merge into `.claude/settings.json`. Must include the `hooks` top-level key with the appropriate event array. The hook should enforce the statement as strictly as possible while avoiding false positives.
- **explanation** — A 2-3 sentence explanation of what this hook does, when it fires, and why programmatic enforcement (100% compliance) is better than advisory-only (~80% compliance via CLAUDE.md).
- **applyInstructions** — Brief instructions for where to put this config. Use project-level `.claude/settings.json` for project-specific rules or `~/.claude/settings.json` for universal rules. Mention that changes take effect on the next Claude Code session.

Important:
- Prefer `command` handlers for objective, verifiable rules (file checks, grep patterns)
- Prefer `prompt` handlers for subjective or complex rules that need judgment
- Keep commands simple and portable (bash, grep, jq)
- Use `$TOOL_INPUT` to inspect tool arguments when needed
- Return ONLY the JSON object, no markdown fences or extra text
